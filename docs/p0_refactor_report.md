# HGA-SP P0 改造报告

日期：2026-07-28

## 1. 范围与结论

本轮完成五项 P0 改造：

1. 路径提交与种群准入解耦；
2. 用结构重复判定替代“目标值相同即重复”；
3. Search Route Archive 与 Master Column Pool 双层路径池，以及精确列支配；
4. 移除经验性路线槽上限，改用严格安全的客户数上界；
5. mdEAX `paper-compatible` / `corrected` 双模式。

这些改造均已通过独立定向测试和项目总回归。当前证据证明的是实现不变量、
可行域安全性和局部数据结构效果；最终解质量和单位 CPU 时间的收益仍应在固定
实例、种子和预算下通过配对消融实验判断。

## 2. P0-1：路径提交与种群准入解耦

### 修改

每个完整可行 HGA/SP 候选在任何种群重复、配置匹配或替换决策之前，统一调用
`RoutePool::submitFeasibleIndividual()`。完整解目标值均值只保留为诊断统计，
不再决定路线是否有资格进入池。

### 不变量

- 不可行候选不能越过路线提交边界；
- 可行候选即使随后被种群拒绝，其路线仍会被检查和提交；
- 有序路线自身仍执行哈希去重；
- SP 注入不会因再次调用普通种群入口而重复计数。

### 定向证据

`route_pool.admission_decoupling` 构造两个完全相同的可行个体：

- 种群大小保持为 1；
- 可行来源提交计数从 1 增至 2；
- 路线池仍保持 2 条唯一有序路线。

这证明路线信息流已经与种群成员资格解耦。

## 3. P0-2：结构重复判定

### 修改

`Individual::hasSameRouteStructure()` 使用以下规范描述：

```text
已开启仓库标记
+ sorted(depot_id, directed_customer_sequence)
```

路线槽位编号不进入签名；仓库开启状态、路线所属仓库以及路线内有向客户顺序均
进入签名。目标值相等只作为低成本预筛选，不再直接导致拒绝。

### 定向证据

`population.structural_duplicate` 构造目标值完全相同的三个解：

- `{(0,1),(2,3)}`；
- `{(0,2),(1,3)}`；
- 第二个解仅交换路线槽位后的克隆。

前两个结构不同的等成本解均进入种群，第三个结构克隆被拒绝，最终种群大小为 2。

## 4. P0-3：双层路径池与精确列支配

### 修改

- Search Route Archive 以 `(depot, ordered sequence)` 为身份，保留有向路线结构；
- Master Column Pool 以 `(depot, sorted customer set)` 为列身份；
- 同一 Master key 始终保留行驶成本最低的已知可行访问顺序；
- Master Pool 裁剪后重新遇到该 key 时，从档案中的最低成本版本恢复；
- SP 只读取压缩后的 Master Column Pool。

两层档案均以 `sp.max_pool_size` 为硬上限。Search Archive 已满时只拒绝额外历史
记录，候选仍可竞争 Master Column Pool；相应 discard counter 进入诊断统计。
因此双层设计不会再以“保留全部历史路线”为代价造成内存无界增长。

### 精确性证明

对同一仓库 `d` 和同一客户集合 `S` 的两条已验证可行路线 `r1,r2`：

- 客户精确覆盖系数相同；
- 仓库归属系数相同；
- 总载重由 `S` 的需求唯一决定，因此仓库容量系数相同；
- 每条路线的车辆固定成本相同；
- 唯一可能不同的是行驶成本。

若 `c(r1) <= c(r2)`，任意包含 `r2` 的主问题解都可用 `r1` 替换而不改变任何
约束可行性，且目标值不增加。因此删除 `r2` 是精确支配，不要求距离矩阵对称。

### 定向证据

`route_pool.column_dominance` 使用同一仓库、同一客户集合的两条有向路线，成本
分别为 102 和 48：

- Search Archive 保留 2 条有序路线；
- Master Pool 从 2 个候选压缩为 1 列；
- Master Pool 最终保留成本 48 的访问顺序；
- 记录 1 次成本改进替换。

该构造中的主问题列数减少 50%，这只是结构测试结果，不代表真实算例的平均压缩率。

## 5. P0-4：严格安全的路线表示界

### 修改

原 CLRP 经验公式：

```text
min(ceil(1.2 * totalDemand / Q) + 5,
    3 * ceil(depotCapacity / Q))
```

被统一替换为以下更紧的安全界。设客户数为 \(n\)，零需求客户数为 \(z\)，正需求
客户中的最小需求为 \(q_{\min}\)，仓库容量为 \(Q_d\)：

\[
U_d=\min\{n,\ z+\lfloor Q_d/q_{\min}\rfloor\}.
\]

当没有正需求客户时第二项只取 \(z\)。底层对象布局至少保留一个槽位，但容量和
精确覆盖约束仍决定其是否能使用。SP 中相同的表示约束默认关闭；显式开启时加入
的也只是这个冗余安全界。

### 安全性证明

精确覆盖要求每个客户恰好属于一条所选路线。每条非空路线要么含至少一个零需求
客户（此类路线最多 \(z\) 条），要么含至少一个正需求客户。后者每条至少消耗
\(q_{\min}\) 仓库容量，因此最多
\(\lfloor Q_d/q_{\min}\rfloor\) 条；同时所有非空路线总数仍不超过 \(n\)。

该证明同时适用于 CLRP 和 CLRP-TW，也允许时间窗迫使所有客户使用单客户路线的
极端情形。

### 定向证据

`representation.safe_route_bound` 构造 6 个客户、车辆容量 100、仓库容量 6
的实例。旧经验公式只给 3 个槽位；新表示分配 6 个槽位，并成功导入 6 条单客户
路线且通过完整可行性检查。测试还覆盖容量/最小正需求收紧、混合零需求以及全部
零需求客户三种边界。

## 6. P0-5：mdEAX 双模式

### 修改

AB-cycle 起点同时存在父边和母边时：

- `paper-compatible`：保持参考实现行为，随机位为 0 或 1 都选择父边；
- `corrected`：随机位 0 选择父边，随机位 1 选择母边。

默认是 `paper-compatible`，因此旧实验行为保持兼容。配置入口：

```text
--eax-mode paper-compatible|corrected
HGASP_EAX_PARENT_MODE=paper-compatible|corrected
```

显式命令行参数优先于环境变量。有效模式写入控制台日志和 `solution.json`。

### 定向证据

`crossover.eax_parent_mode` 对父边独占、母边独占、双方均可用且随机位为 0/1 的
所有策略分支进行确定性断言。`instance.mode_and_parser` 同时验证默认不覆盖模式
以及 `--eax-mode=corrected` 的命令行解析。
